# a0-56 — the playtest log survives the walk back to the menu

**The report (developer, 2026-08-16):** *"because it said i never left the main menu
but i was in the pause menu in the middle of a match"*. They were right and the log
was wrong — and the Director believed the log over the person and reported back that
the session never left the home screen.

**The cause:** the log lived in a module-level singleton and nothing persisted it.
Returning to the menu is a page navigation (`exitToMenu` → `location.assign`, and
`location.reload()` on the end screen and the error-retry paths), so the singleton
died with the page and a fresh log booted in its place. Both logs sent on 2026-08-15
and 2026-08-16 carry the same fingerprint — five events, 8–12 seconds, `dropped: 0`
— which is the boot sequence and nothing else.

## What is in here

Everything was produced by `capture.mjs` in one run against the preview bundle
(`npm run build && npx vite preview --port 4196`, then
`node evidence/a0-56-playtest-log/capture.mjs`). Nothing is stubbed except the
storage denial described below: the match is the sim's own, the clicks are real
clicks at the points the client drew its own controls, the navigation is the
client's own `exitToMenu`, and each `.json` is the bytes Chromium saved when
DOWNLOAD LOG was pressed.

The captured session is the developer's, step for step:

1. boot into an offline match and play it (~15 s of real thrust and fire);
2. **ESC → EXIT → LEAVE** — the pause menu's own way out, which navigates the page;
3. on the menu, **PLAY → PLAY SOLO → RUSH!** into a second match;
4. **ESC → DOWNLOAD LOG**, and read the file back off disk.

| file | what it is |
| --- | --- |
| `after-return-to-menu.json` | the export **with the fix**. This is the deliverable the brief asks for. |
| `without-persistence.json` | the same script with `sessionStorage` denied — which is the pre-a0-56 client, since with no store the log is memory-only. |
| `manifest.md` | both files' headers, tallies and first ten timeline lines, generated by the script. |
| `pause-download-log-*.png` | the pause menu each export was taken from. |
| `capture.mjs` | the script. Re-runnable. |

## What the two files say

**`after-return-to-menu.json` — 11 events, `restored: 5`, `coverage: "match"`.**
The first match is still in the file, and it is still where it happened:

```
      0ms  session session start
     20ms  note    Planet Rush build 3758871* built 2026-08-16T02:40:46.271Z
     29ms  note    webgl
    160ms  match   match start             ← the first match
  15245ms  match   exit to menu            ← LEAVE, on the timeline
  16040ms  session restored after reload   { events: 5, dropped: 0, gapMs: … }
  16040ms  session session start           ← the page that replaced it
  16211ms  connect front door idle
  …        match   match start             ← the second match
```

Read the two properties the brief names off those numbers: the carried events keep
the instants they happened at (`160ms`, `15245ms` — not rewritten to "now"), and the
new page load's events **follow** them on the same axis rather than restarting at
zero. The seam is named rather than hidden: `restored after reload` says how much
came back and how long the reload cost.

**`without-persistence.json` — 5 events, `restored: 0`.** Fifteen seconds of match,
gone. What is left is the boot sequence of the page that replaced it — session start,
the build note, the webgl probe, `front door idle` — which is the fingerprint of both
logs the developer actually sent. `dropped: 0`, a valid schema, and a confident
summary line naming the build and the viewport: every signal in the file still says
"good capture". That is the whole reason this brief exists.

One honest caveat about that second file: it reads `coverage: "match"` rather than
`boot-only`, because the *second* match's own `match start` line is in it — this is
the fixed build with storage taken away, not the old bundle. On the shipped client
there was no `match start` line on the offline path at all (only `attachSessionLog`
filed match events, and it runs for online sessions only), so the same file would
have read `boot-only` there. Both halves of that gap are closed on this branch: the
match announces itself on the timeline whichever transport it is on, and the export
says in one field whether a match is in it.
