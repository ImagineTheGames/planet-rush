------------------------------------------------------------------------------
a0-77 (the `?` help affordance on every settings row) re-baselined three
baselines. While it sat unshipped for six hours, a0-79 (menu plate geometry and
the void behind the menus) re-baselined the same three and merged first. PR #452

merged CODE draws all of it, so the only correct baseline is a frame rendered

`git merge origin/main` auto-merged everything else. The merge was checked for
sense and not only for text: merged `src/ui/settings.ts` lays the rows out
through a0-79's `menuColumnWidth`/`menuColumnBand` and THEN maps a0-77's
`helpRect` over the resulting rows, and merged `src/ui/settings-view.ts` draws
the `?` control and sits on a0-79's `./menu-backdrop`. Neither brief's code was
dropped by the merge.

NOTE — where B2 is a no-op, and why that is not a broken merge
------------------------------------------------------------------------------
The brief asks that both changes be visible in each frame. A is, in all four. B
is, in all four — but B2, the margin, only MOVES at 844x390. On the desktop the
cap was already bitten at 680; at 798x384 the floor wins. Those are a0-79's own
documented outcomes at those two widths, reproduced here by measurement rather
than assumed, and the frames agree with them to the pixel. Where B2 does not
move, a0-79's visible contribution to the screen is B1, the void — and that IS
present in every frame. So nothing is missing from the merge; the margin is
width-dependent by design.

The measurements, before and after, read off the shipped client and not
re-derived: evidence/a0-85-settings-goldens/margins.txt.

HOW THEY WERE MADE
------------------------------------------------------------------------------
In the studio container, against this branch's own production bundle, on a
private port. LESSONS §5 is the rule; a0-06's trap is the reason for the port:
the committed config pins 4173 with `reuseExistingServer: !CI`, several lanes
share this box, and a rebake on the default port can silently bake another
lane's bundle into this branch.

  rm tests/mobile/goldens.spec.ts-snapshots/{desktop,phone-landscape,phone-portrait}-settings-*.png
  PREVIEW_PORT=4285 npm run test:mobile -- --update-snapshots --grep "settings screen"
    -> 3 passed, all three written ("A snapshot doesn't exist ... writing actual")

  PREVIEW_PORT=4285 npm run test:mobile -- --grep "settings screen"
    -> 3 passed, at the SHIPPED tolerance, nothing edited

DELETING the three PNGs is what forces the rebake here, and it replaces the
house `maxDiffPixelRatio: 0` edit that a0-03/a0-41/a0-77 all had to make and
then remember to revert. The reason that edit exists is that at 0.01 a PASSING
test is not rewritten, so a re-baseline run can report success having changed no
pixels — and a0-77's own notes record that its desktop settings frame passed at
0.01 while stale. A missing snapshot is written regardless of tolerance, which
buys the same guarantee without touching QA's file. `tests/mobile/goldens.spec.ts`
is byte-identical to its committed state: `git status` on it is clean, and its
tolerance is untouched (it is the right number; it exists for font/GPU
antialiasing).
