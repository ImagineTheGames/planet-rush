AFTER — main must still fire, and everything after `ci` must still run. Three
pieces of evidence, none of which required pushing to main or deploying:

  b1. THE `push` TRIGGER STILL FIRES FOR A BRANCH NAMED IN `branches:`.
      Proved on a throwaway branch whose own copy of ci.yml adds itself to the
      list — `branches: [main, scratch/a0-83-trigger-probe]` — and changes
      nothing else:

        $ git push origin scratch/a0-83-trigger-probe
        $ gh run list --branch scratch/a0-83-trigger-probe

          32094382562  push  63a22b1b  2026-08-18T03:08:19Z  success   <- 1 run

        Typecheck, test, build                                 success
        Perf gate — submission budget (draw calls, entities)   success
        Boot from the deploy subpath                           success
        Mobile emulation (Playwright) — shard .../...          skipped
        Mobile emulation (Playwright)                          skipped
        Deploy to GitHub Pages                                 skipped
        Verify live deploy boots                               skipped
        Ping ntfy (tagged release)                             skipped

      Exactly one run, and the workflow parsed and executed — so the new `on:`
      + `concurrency` YAML is valid, and a `push` to a ref in `branches:`
      still starts the pipeline.  The five skips are the shipping gates
      correctly declining a ref that is neither `refs/heads/main` nor
      `refs/tags/v*`: they are live and evaluated, not dead.

  b2. NOTHING BELOW THE `on:` BLOCK MOVED.  The entire non-comment diff
      against main is seven lines, all of them in `on:`/`concurrency`:

        $ git diff main..HEAD -- .github/workflows/ci.yml \
            | grep -E '^[+-]' | grep -vE '^[+-]\s*#|^(\+\+\+|---)'

          -    branches: ['**']
          +    branches: [main]
          +  workflow_dispatch:
          +
          +concurrency:
          +  group: ${{ github.workflow }}-${{ github.event.pull_request.number || github.run_id }}
          +  cancel-in-progress: true

      No `if:` expression, no `needs:`, no step. `deploy`, `verify-live` and
      `notify` are byte-identical, and `main` is in the branch list, so the
      run in the BEFORE column above is the run main keeps getting.

  b3. THE SHAPE IS ALREADY PROVEN IN THIS REPOSITORY.
      `.github/workflows/deploy-server.yml` has used `workflow_dispatch` +
      `push: branches: [main]` all along, and fires on every main push:

        32085944175  push  main  success  2026-08-18T00:49:09Z
        32073070977  push  main  success  2026-08-17T21:49:34Z
        31960567385  push  main  success  2026-08-16T17:05:46Z
        31912007263  push  main  success  2026-08-15T22:23:36Z

      Note 32085944175 / 32073070977 — the same two main pushes that produced
      CI runs 32085944154 / 32073070975 above.

  WHAT IS NOT PROVED PRE-MERGE, AND WHY: `Deploy to GitHub Pages` publishes to
  the live URL and `Ping ntfy` posts to the classroom topic. Firing either from
  a probe would mean deploying non-main content to the players' URL, which is
  not a platform agent's call to make. The end-to-end run is this PR's own
  merge commit; its run id is appended below when it lands.

  RESULT (b):  1 full run (deploy + verify-live)  ->  1 full run, unchanged.

AFTER — the risk here is not the `v*` glob, which is untouched; it is that
adding a `branches:` narrowing might stop tag pushes matching at all. It does
not: a `push` block carrying both `branches:` and `tags:` fires when EITHER
matches. Proved with a tag that deliberately does NOT match `v*`, on the probe
branch whose ci.yml adds a second glob `tags: ['v*', 'ci-probe-*']`:

  $ git tag ci-probe-a0-83 && git push origin ci-probe-a0-83
  $ gh run list --branch ci-probe-a0-83

    32094423528  push  63a22b1b  2026-08-18T03:08:57Z  success       <- 1 run

    Boot from the deploy subpath                           success
    Typecheck, test, build                                 success
    Perf gate — submission budget (draw calls, entities)   success
    Mobile emulation (Playwright) — shard .../...          skipped
    Mobile emulation (Playwright)                          skipped
    Verify live deploy boots                               skipped
    Deploy to GitHub Pages                                 skipped
    Ping ntfy (tagged release)                             skipped

  One run, from the `tags:` half of a `push` block whose `branches:` half did
  not match — which is the property under test. `Deploy` and `Ping ntfy` skip
  because `startsWith(github.ref, 'refs/tags/v')` is false for
  `refs/tags/ci-probe-a0-83`, which is the same guard, evaluated, that lets a
  real `v*` tag through. Firing a real `v*` probe would have deployed to the
  players' URL and pinged the classroom, so it was not fired.

  RESULT (c):  1 run per tag  ->  1 run per tag, unchanged.
