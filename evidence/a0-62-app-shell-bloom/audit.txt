a0-62 — the star bloom, measured off the REAL app shell, per device-pixel ratio
==============================================================================

Frames are the shipped `index.html` + `src/main.ts`, built by the app's own
vite.config.ts and served by `vite preview`, driven at four deviceScaleFactors
(evidence/a0-62-app-shell-bloom/capture.mjs). Same 1280x800 CSS viewport, same
frozen boot (?debug=1&freeze=1 => octagon, whose sky is NONE), same camera
offset (-1328,-800) at every ratio. Reach is in CSS px so the rows compare.

THE DESIGN (unchanged by this brief)
------------------------------------
  BLOOM.intensity            0.48
  haloRadiusOf(intensity)    11.24   = 5 + 13 x intensity
  BLOOM.radius               11.24   (agrees; NOT moved by this brief)
  BLOOM.peakAlpha            0.2016
  a bloomed star own r       (2.1630, 2.45]  =>  halo radius (24.31, 27.54] css px

A reach of 0 css px is a star with NO halo at all: a point (and its diffraction
cross, which is stroked geometry rather than a gradient) on bare ground.

THE MECHANISM — the ramp texture, read back off the GPU of the running client
=============================================================================

probe-ramp.mjs paints the falloff ramp 1:1 over opaque black through the
client's own renderer and reads the pixels back, in both boot orders. Over
opaque black a correctly premultiplied ramp reads back rgb = a.

  texel   authored   read back (correct order)   read back (the collapse)   a^2/255
    +10        203                        203                       161     161.6
    +20        154                        154                        93      93.0
    +40         68                         68                        18      18.1
    +60         58                         58                        13      13.2
    +80         21                         21                         1       1.7
   +100          3                          3                         0       0.0
   +110          0                          0                         0       0.0

  The collapsed column IS a^2/255 to the code value. The ramp is premultiplied
  TWICE, so every soft fill paints f^2 where the design says f, and the halo
  falls under one 8-bit code value past ~10 px. Flat fills and the diffraction
  cross never sample the ramp, which is why the star and its spikes survive
  untouched — the developer's photograph exactly.

  UNPACK_PREMULTIPLY_ALPHA_WEBGL is global GL state. pixi 8.6.6 sets it in one
  place only — glUploadImageResource, for image/canvas sources — and
  glUploadBufferImageResource (the ramp, a BufferImageSource) never touches it.
  So the ramp inherited whatever the last font atlas left behind. A page with
  no image texture on it at all — every probe in a0-22/44/45/53, sky-preview,
  the unit suite — leaves it false and draws the halo correctly. That is why
  four rounds of correct measurements coexisted with a broken game.
