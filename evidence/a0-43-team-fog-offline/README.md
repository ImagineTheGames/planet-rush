# a0-43 — shared team fog, proved in the mode the developer actually plays

**SOLO, against bots, in TEAMS — offline, through the real lobby.**

a0-42 shipped shared team vision. Reporting it, the Director said *"solo play is
untouched"* meaning free-for-all, and the developer corrected them:

> *"what do you mean solo play is untouched, do you mean FFA instead? because in
> solo play we can have teams"*

Offline solo-vs-bots is a full TEAMS mode, and it is the mode most matches are
played in. a0-42's evidence names only the harness boot (`?debug=1&sides=2`),
which has no lobby, so the feature could have shipped proven only in the mode
nobody asked about. These frames are the missing half.

The proof is `tests/mobile/team-fog-offline.spec.ts` (two tests, desktop control
profile). Everything here is regenerated by it — this folder composes evidence,
it never produces it.

## What the pair measures

Counted over the 313,600 pixels of the minimap overlay, on the run that produced
these two frames:

| | FFA | TEAMS |
|---|---:|---:|
| arena revealed to the human | 47,536 px | 141,252 px |
| revealed in TEAMS, **fog** in FFA | — | **93,716 px** |
| revealed in FFA, fog in TEAMS | **0 px** | — |
| ore-field hints on the map | 477 px | 2,267 px |

`ffaOnly = 0` is the shape of the feature: free-for-all is teams-of-one, so the
FFA frame's revealed set *is* the coverage the human projects alone — and every
pixel of it is still revealed in TEAMS. Shared vision is a union; it only adds.
Which means the 93,716 px it adds are, by construction, outside every disc the
human projects. No radius is assumed anywhere in that argument.

Per-player, by identity colour (`src/ui/minimap.ts` draws every dot in
`playerColor(owner)`), on the same run:

| slot | side | px on the TEAMS map | of those, outside the human's own coverage | px on the FFA map |
|---|---|---:|---:|---:|
| P0 — you | A | 1,461 | 0 | 1,461 |
| P1 | B | 1,524 | 1,524 | 0 |
| P2 | A | 1,527 | 1,527 | 0 |
| P3 | B | 0 | 0 | 0 |
| P4 | A | 1,524 | 1,524 | 0 |
| P5 | B | 0 | 0 | 0 |
| P6 | A | 1,527 | 1,527 | 0 |
| P7 | B | 0 | 0 | 0 |

That table is the side table the **lobby** authored, read straight off the drawn
pixels: the human's three bot allies are slots 2, 4 and 6, exactly
`defaultTeamForSlot(i) = i % 2` (`src/ui/lobby.ts`), and every pixel of them sits
where the human alone can see nothing. P1 is an **enemy** the human can see only
because a teammate's coverage is over them — the brief's *"an enemy ship sitting
in that area appears on the human's minimap"*, happening on its own in a real
match. Whether an enemy has flown into an ally's sensor by the frame's tick is a
bot's business, so the spec asserts the invariant that holds at every tick
measured (30 through 900) — *every* enemy pixel the human's map carries is one a
teammate bought them — and the staged test below proves the same thing on purpose.

## The staged pair

`?debug=1&freeze=1&sides=2` at a 2v2, driven through a0-42's own
`__teamFogStage` and read back off the minimap layer's drawn-frame seam
(`__minimapStage`). The ally is posted **1,332 world units outside the edge of
every disc the human projects**, so nothing over there can be the human's own
sight.

| | ally on the ENEMY side | ally on YOUR side | after they scout | the tick after they die |
|---|---:|---:|---:|---:|
| coverage discs drawn | 2 | 4 | 4 | **3** |
| enemy ship dots drawn | 0 | 2 | 2 | **0** |
| station dots drawn | 1 | 3 | 3 | 3 |
| ore hints drawn | 5 | 13 | 23 | 23 |
| rivals in the sensed set | — | `[1]` | `[1]` | `[]` |

Read across the last column: the dead teammate's own disc is gone and the rival
who was only under it drops off the map the same tick — live coverage is
recomputed, never remembered — while the stations and the ore field they taught
the human stay. That is the live/remembered split, across a side.

The control is the same harness boot with no sides at all (`?debug=1&freeze=1`):
there is nobody on your side but you, the team's coverage *is* your own disc for
disc, and no rival is sensed through anybody.

## Regenerating

A preview server must be serving the build under test.

```
npm run build && npm run preview -- --port 4173 &
A0_43_CAPTURE=1 npx playwright test tests/mobile/team-fog-offline.spec.ts --project=desktop
node evidence/a0-43-team-fog-offline/side-by-side.mjs
```

Without `A0_43_CAPTURE` the spec writes nothing into the working tree — the same
frames ride every run as Playwright attachments instead, alongside a JSON
attachment carrying the whole census above.

## The seam this brief had to work around

The brief asks for one test that both walks the real lobby *and* reads the
client's minimap seam. Those cannot be the same boot today: `?debug=1` is a
single flag that installs every live-stage seam **and** skips the menu and the
lobby (`src/main.ts:969`, `:1028`). So the proof is in two acts — the lobby one
measured off drawn pixels, the seam one staged in an offline `?debug=1` match —
and they are the same table: the lobby's default TEAMS assignment is
`defaultTeamForSlot(i) = i % 2` and the debug boot's `?sides=2` builds
`(_, i) => i % 2` (`src/main.ts` `readDebugSides`), character for character.

QA does not own `src/`, so this is reported rather than patched. Closing it would
mean separating "install the debug seams" from "skip the front door" — a
Platform/Gameplay call, not QA's.
